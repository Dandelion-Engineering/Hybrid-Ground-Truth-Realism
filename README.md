# Hybrid Ground Truth Realism

**Does the realism of hybrid ground truth change measured spike-sorting accuracy?**

| | |
|---|---|
| **Current phase** | Phase 2 — Execution (host and placement gates in review before the feasibility pilot) |
| **Public state** | `In Progress` |
| **Last updated** | 2026-08-13 |

Spike sorting decides which extracellular spikes came from which neuron. Real recordings have no answer key, so the field grades sorters against **hybrid recordings** — a real recording with synthetic spikes injected at times that are known by construction. The maintainers who built the standard hybrid pipeline wrote down, in print, that they do not know whether their synthetic spikes are realistic enough for the resulting accuracy numbers to mean what the field treats them as meaning. This project tests it: vary the realism of injected spikes along axes the maintainers themselves named, hold every axis-compatible nuisance variable fixed or matched, and measure whether sorter accuracy — and, more importantly, the *ranking between sorters* — moves.

---

## How this project was run

- **This is an automated exploratory research run.** It investigates one question and reports what it found. It is not a confirmatory study, and it is not meant to settle anything.
- **The work was selected and carried out by AI agents.** Choosing this question, doing the work, and writing it up were all done by AI agents working inside a documented framework.
- **A human director sets direction and reads summaries. He does not review the work in detail.** Dandelion Engineering is one person working with a team of AI agents; his part is direction and judgement about what is worth doing, not line-by-line verification of what was done.
- **Negative findings are published as produced.** If the answer comes back no, or comes back inconclusive, that is what gets published — on the same terms as a positive one, and without waiting to see whether it is flattering.
- **This is not reviewed work.** It has not been peer-reviewed, and it has not been checked in detail by a human. While the status above reads `In Progress` you are reading work in progress rather than a result; once it reads `Concluded` you are reading a finished exploratory run, which is still not a reviewed one. **The way to trust any of it is to check it** — which is what the reproducibility packet is for.

- **2026-08-13 — The rule that keeps the two comparison groups alike was matching them on a label nobody had read, and the label names the narrowest possible thing.** For the experiment's central comparison to mean anything, the group of injected waveforms drawn from the target brain region and the group drawn without regard to region have to be alike in everything except region. One of the things the contract requires them to match on is how many different **source recordings** each is drawn from — because an arm drawn from four recordings compared against an arm drawn from one is partly a comparison of recordings wearing a region label. Every draft so far has counted the donor library's `dataset` column for that. Reading the parser rather than counting the column shows `dataset` **is one probe insertion** — one probe, one time, one animal — and that the session and the animal are both derived from that same string. So the three levels nest, and matching the narrowest one does not match the others: of the **66,045** four-recording control groups available at the size that actually applies, **28,621 (43%) span fewer animals than the four-animal group they would be compared against, and 74 of them come from a single animal.** The check now runs at all three levels and falls back to the contract's original single-level version only where the stronger one admits no valid pairing — which costs no feasibility and, because the wider counts are *determined* by the narrower one, actually shrinks the search by 43% before any work starts. The same review found a second gap of a different kind: the project had carefully pinned the **rules** of the experiment in advance, including two random seeds and the formula each was computed from, but not the **dice** — the physical positions each injected waveform is placed at were described only as "randomized," with no stated source, and every quantity the two arms are matched on is measured at those positions. Nothing prevented drawing them, disliking the balance report, and drawing again. Those draws must now come from a recorded formula and a recorded seed, one stream per injection; the randomness the design needs is untouched, and only the ability to roll twice and keep one is removed. - **2026-08-13 — One of the remaining checks is whether the recording's probe drifts, and the ready-made number for it turned out to measure something else.** Brains and probes move slightly during a recording, and a sorter has to cope with that; too much movement and the recording is a bad host for this experiment. The archive publishes a drift column, so the obvious move was to use it. Reading its own published description says not to: it adds up every small wobble between consecutive spikes rather than measuring how far the probe actually ended up moving — so a probe that drifts away and comes back scores the same as one that drifts and stays — it grows with how *busy* the recording is rather than how much it moves, and the description states outright that it is not actual electrode displacement. The busyness part is specifically disqualifying here, because a later stage of this experiment manipulates exactly that: picking a host for scoring low on a busyness-linked number would mean picking a quiet recording, which would bias that stage before it started. A replacement has been defined from data the archive already carries — per-spike depth estimates — and it measures net displacement instead, with a built-in check that compares each recording against a scrambled version of itself, so that a reading which is really just measurement noise is reported as noise rather than as a quiet probe. The cut-off, and the single relaxation allowed if nothing passes it, are both written down **now, before any recording has been measured**, so that neither can be chosen later to fit what the numbers turn out to be. **Still no host chosen, no donor selected, no generator or sorter run, and no scientific result.**

- **2026-08-13 — Review corrected that drift proposal before it measured a recording, and closed the separate donor-matching prose rule.** The replacement drift statistic is a worst-window **peak-to-peak excursion**, not net displacement; a probe that moves away and returns must remain visible. The first draft would also have rejected a genuinely quiet recording merely because it looked like its own no-drift control, and claimed that movement below one 20 µm contact-row pitch was physically invisible. The repaired rule instead requires both the observed excursion and the control-derived noise floor to fit below the predeclared tolerance, treats 20 µm as a declared one-row judgement rather than a resolution claim, fixes the randomization and strict-to-relaxed search order in advance, and states that choosing a host through a Kilosort-family-derived trace can condition the measured interaction rather than assuming the effect cancels. That revised host/drift state is back with its owner for same-state review. Separately, both agents now approve the exact pre-pool donor-matching prose rule; its schedule/placement specification, implementation, synthetic tests, real manifest and every execution gate still do not exist and remain separate. **No host is pinned, no candidate drift value has been read, no donor is selected, no generator or sorter has run, and no scientific result exists.**

- **2026-08-13 — The corrected drift check was accepted, and then built and tested on recordings where the right answer was known in advance.** The correction from the previous round stands: a recording that genuinely does not move must not be rejected for resembling a recording that does not move. Checking it rather than agreeing with it turned up something worth stating, because it is the argument a tightened rule owes and this one does not need — the repaired rule can only ever *accept more* recordings than the version it replaced, never fewer. Every recording the old rule would have passed still passes; what changes is that the quietest ones now pass too. The check itself is now written and run. It was tested against made-up recordings built so the answer is known before the test: a probe moved a stated distance recovers that distance; a probe that drifts away and comes back reports the size of the round trip rather than zero; a recording deliberately left one neuron short during a single minute is refused as unmeasurable and says which minute and how many neurons. **The three defects the previous review round caught are now permanent tests rather than corrected paragraphs** — a future session cannot quietly restore any of them without something going red. Fifty-three checks, none failing, at the full number of random shuffles the real check will use, which takes three and a half seconds and so never has to be argued about on cost. One reading of the specification that the code forced into the open has been handed back to the other agent to confirm or change rather than left as an accident of how it happened to be written. **No recording has been measured, no host is pinned, no donor is selected, no generator or sorter has run, and no scientific result exists.**

- **2026-08-13 — A correction to this log's earlier claim that the reproducibility packet was verified runnable: it was verified the wrong way round.** The packet was tested by copying its folder to an isolated place, building a fresh environment and running the printed commands, and five of the ten steps reproduced their recorded output exactly. That test was real, and it does not cover what a reader actually does. A reader does not copy a folder — they **clone the repository**, and on Windows a clone rewrites line endings on the way out. So the bytes a reader receives are not the bytes that were tested. This was measured rather than guessed: cloning this repository locally and comparing every packet file against the tested one, **thirty of forty-two differ.** Two of those matter — the frozen copy of the upstream waveform metadata, whose entire purpose is to be identical to what was downloaded and whose published checksum does not survive the trip, and the recorded output of one of the five steps claimed to reproduce exactly, which a Windows reader would therefore find failing through no fault of their own. On Linux and macOS the conversion is normally off and the problem does not arise. **Nothing measured or agreed by either agent is affected** — every checksum the two agents exchange is taken inside one working copy, and all of them are still correct. The fix is a single well-known configuration file, and it has deliberately **not** been applied yet: it changes what every future download of this repository produces, in a packet both agents co-own, so it goes through review rather than into the closing minutes of the session that found it. It is written up in full, with the proposed fix and the check that would confirm it. The general lesson is one this project had already learned in a narrower form — a set of instructions you have not executed is a guess — and this is the same thing one level up: **a delivery path you have not exercised is a guess.**
